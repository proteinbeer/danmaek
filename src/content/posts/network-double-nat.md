방마다 와이파이를 쓰기 위해 통신사 공유기에 개인 공유기를 하나 더 연결하는 경우가 있습니다. 인터넷과 유튜브가 잘 되니 별문제가 없어 보이지만, 온라인 게임에서는 NAT 타입이 엄격해지거나 파티 참가가 실패하고 포트포워딩이 작동하지 않는 일이 생길 수 있습니다.

원인은 공유기가 두 대라는 사실 자체가 아닙니다. 두 장비가 모두 ‘공유기’ 역할을 하면서 각각 NAT와 DHCP를 처리하는지가 중요합니다. 두 번째 장비가 AP 모드라면 공유기가 두 대 있어도 이중 NAT가 아닐 수 있습니다.

## 1. 가장 먼저 두 번째 공유기의 WAN IP를 봅니다

예를 들어 집의 연결이 다음과 같다고 가정해보겠습니다.

```
인터넷 → 통신사 공유기 → 개인 공유기 → PC
```

개인 공유기의 관리 페이지에서 WAN 또는 인터넷 IP를 확인합니다.

여기에 192.168.x.x, 10.x.x.x, 172.16.x.x~172.31.x.x 같은 사설 IP가 표시된다면 개인 공유기는 바깥쪽 장비에서 주소를 하나 받아 사용하고 있는 것입니다.

PC에서 확인한 내부 IP도 또 다른 대역이라면 구조가 더 분명해집니다.

```
통신사 공유기: 192.168.0.1
개인 공유기 WAN: 192.168.0.10
개인 공유기 LAN: 192.168.1.1
PC: 192.168.1.20
```

이런 구성이라면 PC에서 인터넷으로 나갈 때 192.168.1.x에서 한 번, 다시 192.168.0.x에서 한 번 주소 변환을 거칠 수 있습니다. 이것이 전형적인 가정용 이중 NAT 구성입니다.

## 2. 인터넷은 잘 되는데 왜 게임만 문제가 생길까

웹사이트를 열거나 영상을 보는 연결은 대부분 집 안의 기기가 먼저 외부 서버에 접속합니다. 이런 일반적인 사용에서는 NAT가 두 단계여도 사용자가 문제를 알아차리지 못하는 경우가 많습니다.

반면 일부 온라인 게임, 콘솔 파티, P2P 연결, 개인 서버, 원격 접속은 외부에서 집 안의 특정 기기까지 연결 경로가 필요합니다.

NAT가 한 단계라면 공유기 하나만 처리하면 되지만 이중 NAT에서는 바깥 공유기와 안쪽 공유기를 모두 통과해야 합니다.

그래서 인터넷 속도 측정에서는 정상적인 수치가 나오면서도 게임 NAT 상태나 포트 개방 테스트에서만 문제가 나타날 수 있습니다.

## 3. 포트포워딩을 했는데도 안 되는 이유

PC의 주소가 192.168.1.20이고 게임에 특정 포트를 열어야 한다고 해보겠습니다.

개인 공유기에서 해당 포트를 192.168.1.20으로 전달하는 것만으로는 부족할 수 있습니다. 외부에서 들어온 연결은 그보다 먼저 통신사 공유기를 만나기 때문입니다.

이중 NAT를 그대로 유지한다면 일반적으로 연결 경로 전체가 이어지도록 두 장비의 설정을 맞춰야 합니다.

```
외부
↓
통신사 공유기
↓
개인 공유기
↓
PC
```

설정할 장비가 늘어날수록 IP 변경이나 규칙 누락 때문에 문제가 생기기도 쉬워집니다. 특별히 네트워크를 분리해야 하는 이유가 없다면 이 구조를 유지하면서 포트 규칙을 계속 추가하는 것보다 NAT 단계를 하나로 줄이는 편이 단순합니다.

## 4. 와이파이 확장이 목적이라면 AP 모드가 편합니다

두 번째 공유기를 설치한 이유가 방 안의 와이파이 신호를 넓히거나 유선 포트를 추가하기 위해서라면 두 번째 장비가 별도의 라우터일 필요는 없습니다.

공유기가 지원한다면 AP(Access Point) 모드로 변경할 수 있습니다. 이 경우 첫 번째 공유기가 IP 주소 할당과 NAT를 담당하고 두 번째 장비는 같은 네트워크를 전달하는 접속 지점 역할을 합니다.

변경 전:

```
192.168.0.x → 두 번째 공유기 → 192.168.1.x
```

AP 모드 변경 후:

```
첫 번째 공유기 → 두 번째 장비 → 같은 192.168.0.x 대역
```

모드를 바꾼 뒤 두 번째 장비에 연결된 PC나 콘솔이 첫 번째 공유기와 같은 IP 대역을 받는지 확인하면 됩니다.

제조사에 따라 AP 모드를 ‘액세스 포인트’, ‘브리지’, ‘AP/Bridge’처럼 다르게 표시할 수 있으므로 메뉴 이름만 보고 설정하지 말고 해당 모델의 설명서를 확인하는 것이 좋습니다.

## 5. 통신사 공유기를 브리지로 바꾸는 방법도 있지만

반대로 통신사 장비의 라우터 기능을 끄고 개인 공유기 하나가 NAT를 담당하게 만드는 구성도 가능합니다.

다만 IPTV나 인터넷 전화가 통신사 장비 설정과 연결돼 있다면 브리지 모드 변경 후 서비스에 영향을 줄 수 있습니다. 통신사 장비를 직접 변경하기 전에 해당 회선에서 브리지 모드를 지원하는지 확인하는 편이 안전합니다.

단순히 개인 공유기로 와이파이 범위를 늘리는 것이 목적이라면 통신사 장비를 건드리기보다 개인 공유기를 AP로 전환하는 쪽이 보통 작업 범위가 작습니다.

## 6. 이중 NAT를 없앴는데도 WAN IP가 이상하다면

집 안의 라우터를 하나로 정리했는데도 포트포워딩이나 외부 접속이 되지 않는다면 그때는 CGNAT 여부를 확인할 차례입니다.

공유기 관리 페이지에 표시되는 WAN IP와 인터넷에서 확인되는 공인 IP를 비교합니다. 집에 라우터가 하나뿐인데 두 주소가 서로 다르다면 통신사 구간에서 주소 변환이 한 번 더 이루어지고 있을 가능성이 있습니다.

이 경우 집 안의 이중 NAT와는 해결 방법이 다릅니다. 공유기 설정을 계속 바꾸기보다 인터넷 제공업체에 공인 IPv4 제공 여부를 문의해야 할 수 있습니다.

## 공유기 두 대를 꼭 없앨 필요는 없습니다

이중 NAT를 해결한다는 말이 공유기 한 대를 물리적으로 치워야 한다는 뜻은 아닙니다.

집이 넓다면 장비 두 대 이상을 그대로 사용하면서 라우팅과 NAT를 담당하는 장비만 하나로 만들 수 있습니다. 첫 번째 장비를 라우터로 두고 나머지를 AP로 사용하는 방식입니다.

반대로 게스트망, 실험용 네트워크, 업무망처럼 네트워크를 의도적으로 분리한 환경이라면 이중 NAT를 유지할 이유도 있습니다. 이 경우에는 포트포워딩과 외부 접속 설정 역시 두 단계 구조를 전제로 구성해야 합니다.

게임 때문에 이중 NAT가 의심된다면 인터넷 속도부터 만질 필요는 없습니다. 두 번째 공유기의 WAN IP와 PC의 IP 대역을 먼저 확인해 실제로 NAT가 두 번 일어나는 구조인지 확인하는 것이 가장 빠른 출발점입니다.
