게임 서버와 NAS, 원격 접속을 위해 포트포워딩을 설정했는데 외부에서 연결되지 않는 경우가 많습니다. 공유기 화면에 포트 번호를 넣는 것만으로는 충분하지 않고 대상 프로그램이 실제로 그 포트에서 기다리고 있어야 하며 방화벽과 공인 IP 구조까지 맞아야 합니다.

외부 포트 검사에서 닫힘으로 나온다고 공유기 설정이 틀렸다고 단정하면 안 됩니다. 대상 프로그램이 실행되지 않은 상태라면 포워딩 규칙이 맞아도 응답할 서비스가 없어 닫힌 것처럼 보일 수 있습니다.

1. 서버 프로그램부터 실행

먼저 같은 PC 안에서 서버 프로그램이나 서비스가 정상적으로 실행되는지 확인합니다. 게임 서버라면 로컬 PC에서 해당 포트를 실제로 사용 중인지 확인하고 NAS라면 같은 집 안에서 내부 주소로 접속되는지 봅니다.

내부 접속도 실패하는데 외부 포트포워딩부터 고치는 것은 순서가 거꾸로입니다. 로컬 서비스가 정상이라는 기준을 만든 뒤 공유기 밖에서 접근해야 합니다.

2. 대상 PC 주소 고정

포트포워딩 규칙은 보통 내부 IP 주소를 대상으로 만듭니다. PC가 재부팅된 뒤 DHCP 주소가 바뀌면 규칙은 예전 주소를 계속 가리켜 외부 접속이 끊깁니다.

공유기의 DHCP 예약으로 서버 PC 주소를 일정하게 유지하는 편이 좋습니다. PC에 직접 고정 IP를 넣는 것보다 네트워크 설정을 공유기 한 곳에서 관리하기 쉽습니다.

3. 윈도우 방화벽

공유기가 포트를 PC까지 전달해도 윈도우 방화벽이 프로그램의 수신 연결을 막으면 접속은 실패합니다. 프로그램 설치 때 만든 방화벽 규칙이 현재 네트워크 프로필에서 허용돼 있는지 확인합니다.

테스트를 위해 방화벽 전체를 장시간 끄는 것보다 필요한 프로그램과 포트 규칙을 확인하는 편이 안전합니다. 외부에 서버를 공개하는 만큼 최소 범위만 허용하는 것이 좋습니다.

4. 이중 NAT와 CGNAT

공유기가 두 대면 바깥 공유기에서도 포워딩이 필요할 수 있습니다. 집 공유기의 WAN 주소가 사설 IP라면 이중 NAT나 통신사 CGNAT를 확인해야 합니다.

CGNAT 환경에서는 집 공유기에서 규칙을 아무리 정확히 만들어도 인터넷에서 공유기까지 직접 들어오지 못할 수 있습니다. 이때는 통신사의 공인 IP 옵션이나 IPv6, VPN 기반 대안을 검토해야 합니다.

일부 공유기는 집 안에서 자신의 공인 주소로 다시 들어오는 NAT 루프백을 지원하지 않습니다. 외부 접속은 정상인데 같은 와이파이에서 공인 주소로 테스트하면 실패하는 경우가 있습니다.

휴대폰의 와이파이를 끄고 모바일 데이터에서 접속해보면 진짜 외부 테스트가 됩니다. 포트포워딩은 서버 프로그램, 내부 IP, 방화벽, NAT 구조, 외부 테스트 순서로 보는 것이 가장 빠릅니다.

외부에 포트를 열었다면 서비스 프로그램과 운영체제를 최신 상태로 유지하고 필요하지 않은 포트는 닫아두는 편이 좋습니다. 연결 문제를 해결하는 것과 인터넷에 불필요한 서비스를 노출하지 않는 것은 함께 관리해야 합니다.

포트포워딩 화면은 전체 과정의 한 부분일 뿐입니다. 내부 서비스가 살아 있는지부터 확인하고 공유기 밖으로 한 단계씩 나가야 어디에서 연결이 막히는지 정확히 찾을 수 있습니다.

포트 번호를 바꿔 시험할 때는 서버 프로그램도 같은 포트에서 대기하도록 함께 변경해야 합니다. 공유기 규칙만 다른 번호로 바꾸면 외부 연결이 PC까지 도착해도 프로그램이 받지 못해 실패합니다.
