랜선을 꽂았는데 Windows가 ’식별되지 않은 네트워크’라고 표시하면 DNS를
바꾸기 전에 PC가 공유기에서 정상적인 네트워크 정보를 받았는지
확인합니다.

## ipconfig에서 IPv4를 봅니다

ipconfig를 실행해 사용 중인 이더넷의 IPv4와 기본 게이트웨이를
확인합니다. 집 공유기가 192.168.0.x를 쓰는데 PC에는 169.254.x.x가 잡혀
있다면 DHCP에서 정상 주소를 받지 못했을 가능성이 큽니다.

## 기본 게이트웨이가 비어 있는지도 확인합니다

IPv4가 그럴듯해도 기본 게이트웨이가 없다면 수동 IP 설정이 잘못됐거나
DHCP 정보가 제대로 적용되지 않았을 수 있습니다. 최근 직접 고정 IP를
넣었다면 자동 설정으로 되돌려 비교합니다.

## 랜선과 포트를 단순화합니다

정상인 랜선으로 PC를 공유기의 다른 LAN 포트에 직접 연결합니다. 벽면
랜포트나 중간 스위치를 썼다면 테스트 중에는 제외합니다.

자동 IP 상태라면 ipconfig /release와 ipconfig /renew로 주소를 다시
요청할 수 있습니다. renew가 DHCP 서버에 도달하지 못한다면 공유기의 DHCP
기능과 PC까지의 연결 경로를 확인합니다.

정상적인 사설 IP와 게이트웨이를 받았다면 ping 192.168.0.1처럼 자신의
게이트웨이에 응답이 오는지 봅니다. 공유기에는 닿는데 인터넷만 안 된다면
그때 WAN이나 DNS 쪽으로 넘어갑니다.

169.254를 없애려고 아무 192.168.x.x 주소나 직접 넣는 것은 해결책이
아닙니다. 먼저 DHCP가 왜 정상 주소를 주지 못했는지 찾는 것이 핵심입니다.
