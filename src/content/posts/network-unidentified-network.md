랜선을 꽂았는데 윈도우에 식별되지 않은 네트워크가 표시되면 케이블이 연결됐다는 사실만으로 정상이라고 보기 어렵습니다. PC가 공유기에서 IP 주소와 기본 게이트웨이를 제대로 받았는지부터 확인하셔야 합니다.

이 문제는 공유기 초기화보다 현재 주소를 보는 것이 훨씬 빠릅니다. 특히 IPv4 주소가 169.254로 시작하면 윈도우가 DHCP 서버에서 주소를 받지 못해 임시 주소를 스스로 만든 상태일 가능성이 큽니다.

## 1. 169.254 주소의 의미

명령 프롬프트에서 ipconfig를 실행해 IPv4 주소와 기본 게이트웨이를 확인합니다. 집에서 흔히 쓰는 192.168 대역이나 10 대역이 아니라 169.254로 시작한다면 공유기에서 정상 주소를 받지 못한 상태로 보는 편이 맞습니다.

이때 DNS를 바꾸거나 브라우저를 초기화해도 해결될 가능성은 낮습니다. PC와 공유기 사이에서 DHCP 통신이 실패한 것이므로 랜선, 공유기 포트, 랜카드, DHCP 설정 순서로 범위를 좁히는 게 효율적입니다.

## 2. 게이트웨이가 비어 있는 경우

IPv4 주소는 정상처럼 보여도 기본 게이트웨이가 비어 있으면 외부 인터넷으로 나갈 길을 찾지 못합니다. 자동 설정을 쓰는 PC라면 네트워크 어댑터의 IPv4 설정에서 IP 주소와 DNS가 자동으로 받기로 되어 있는지 먼저 확인합니다.

예전에 회사나 다른 집에서 사용하던 고정 IP가 남아 있으면 현재 공유기의 주소 대역과 맞지 않을 수 있습니다. 수동 값을 지우고 자동으로 돌린 뒤 어댑터를 껐다 켜서 새 주소를 받는 것이 안전합니다.

## 3. 랜선과 포트 비교

정상인 짧은 랜선으로 PC와 공유기를 직접 연결해보는 테스트가 좋습니다. 벽면 랜포트나 중간 허브를 거치던 환경이라면 중간 구간을 빼는 것만으로 문제 위치가 바로 드러나기도 합니다.

같은 랜선과 같은 공유기 포트에 다른 노트북을 연결했을 때 정상이라면 PC 쪽 랜카드나 설정 가능성이 커집니다. 다른 기기도 주소를 받지 못하면 공유기 포트나 DHCP 기능을 먼저 봐야 합니다.

## 4. DHCP 주소 다시 받기

윈도우 네트워크 어댑터를 비활성화했다가 다시 활성화하면 DHCP 요청이 새로 진행됩니다. 그래도 바뀌지 않으면 공유기의 DHCP 서버가 켜져 있는지와 주소 풀이 모두 소진된 것은 아닌지 확인합니다.

공유기에 접속 가능한 다른 기기가 있다면 연결된 기기 목록에서 문제가 있는 PC가 보이는지도 확인하시면 됩니다. 목록에 아예 나타나지 않는다면 IP 설정보다 물리 연결이나 랜카드 상태를 의심할 근거가 더 커집니다.

윈도우의 네트워크 초기화는 어댑터와 여러 네트워크 설정을 다시 만드는 강한 조치입니다. VPN이나 가상 어댑터를 사용하고 계시면 설정이 함께 달라질 수 있으므로 처음부터 누르기보다는 앞 단계에서 원인을 좁힌 뒤 사용하는 편이 낫습니다.

식별되지 않은 네트워크라는 문구 자체를 없애는 것이 목표는 아닙니다. PC가 정상 IP와 게이트웨이를 받고 공유기까지 통신되는지 확인하면 해결 방향이 훨씬 선명해집니다.

문제가 해결된 뒤에는 정상 상태의 IPv4 주소와 기본 게이트웨이를 한 번 기록해두는 편이 좋습니다. 다음에 같은 문구가 떠도 정상값과 비교해 DHCP 문제인지 물리 연결 문제인지 훨씬 빨리 판단할 수 있습니다.

공유기 재부팅이 우연히 문제를 풀어줄 수는 있지만 원인을 알려주지는 않습니다. 주소가 어디에서 끊겼는지 확인하는 습관이 같은 증상을 반복해서 겪지 않는 데 더 도움이 됩니다.

이 오류가 재부팅 뒤 잠깐 사라졌다가 다시 나타난다면 랜카드 드라이버와 공유기 DHCP 로그도 확인할 만합니다. 같은 시간대에 다른 기기도 주소를 다시 받는지 비교하면 PC 한 대 문제인지 공유기 전체 문제인지 구분하기 쉽습니다.

## 5. 오류가 다시 생길 때 남길 값

같은 증상이 다시 생기면 문제가 생긴 순간의 IPv4 주소와 기본 게이트웨이을 먼저 확인해 두시는 게 좋습니다. 이어서 정상일 때의 값과 비교해 보시면 원인이 바뀐 것인지 같은 문제가 반복되는 것인지 판단하기 쉽습니다. 169.254 주소나 빈 게이트웨이는 DHCP 단계에서 막혔다는 단서이라는 점이 중요한 단서가 됩니다.

이 단계에서는 DNS 변경과 공유기 초기화를 동시에 하는 것보다 범위를 하나씩 줄이는 편이 낫습니다. 먼저 같은 시간에 다른 기기도 주소를 다시 받았는지 확인하신 뒤 결과가 같다면 다음 단계로 넘어가십시오. 마지막으로 PC 한 대만 반복되면 랜카드 드라이버와 절전 설정까지 확인하시면 단순한 일시 오류와 반복되는 구조 문제를 구분하기 쉬워집니다.
