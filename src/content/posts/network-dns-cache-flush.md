특정 사이트만 열리지 않거나 도메인을 새 서버로 옮긴 뒤 계속 예전 주소로
연결될 때 ipconfig /flushdns를 많이 사용합니다. Windows 캐시에 오래된
주소가 남아 있었다면 효과가 있지만, 한 번 실행한 뒤에도 같다면 같은
명령을 반복할 이유는 없습니다.

## Windows 캐시부터 한 번 비웁니다

명령 프롬프트에서 ipconfig /flushdns를 실행한 뒤 브라우저를 완전히
닫았다 다시 엽니다. 문제가 그대로라면 Windows 캐시 밖으로 범위를
넓힙니다.

## 다른 브라우저에서는 열리는지 확인합니다

Chrome에서만 실패하고 Edge나 Firefox에서는 열린다면 운영체제 전체보다
브라우저의 Secure DNS, 확장 프로그램, 프록시 설정을 먼저 볼 수 있습니다.
모든 브라우저에서 같다면 다음 단계로 갑니다.

## nslookup 결과를 확인합니다

nslookup example.com처럼 문제가 있는 도메인을 조회합니다. 현재 반환되는
IP가 사이트가 사용해야 하는 주소와 맞는지 확인합니다. DNS를 방금
변경했다면 TTL 때문에 이전 정보가 아직 남아 있을 수도 있습니다.

다른 DNS 서버에 직접 질의했을 때만 새 주소가 나온다면 PC 캐시가 아니라
사용 중인 DNS 서버 쪽 갱신 차이일 수 있습니다.

## DNS가 정상이어도 사이트는 안 열릴 수 있습니다

DNS가 올바른 IP를 반환해도 서버 장애, HTTPS 인증서, 프록시, 방화벽
때문에 접속이 실패할 수 있습니다. Windows hosts 파일에 예전 주소를 직접
지정해둔 적이 있다면 그 항목도 확인합니다.

여러 기기에서 동일한 오래된 결과가 나오고 공유기가 DNS를 중계한다면
공유기 재시작이 영향을 줄 수 있습니다. 반대로 한 PC의 한 브라우저에서만
문제라면 공유기 초기화는 범위가 너무 큽니다.

핵심은 캐시 삭제 횟수가 아니라 ’현재 어느 DNS 서버가 어떤 IP를
반환하는가’를 확인하는 것입니다.
