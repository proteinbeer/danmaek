특정 사이트만 안 열리거나 도메인 주소를 바꾼 뒤 예전 서버로 계속 연결되면 DNS 캐시 삭제부터 시도하게 됩니다. 하지만 윈도우 캐시를 지웠는데도 변화가 없다면 문제가 캐시가 아니라 다른 DNS 계층에 있을 수 있습니다.

DNS 정보는 PC 하나에만 저장되는 것이 아닙니다. 브라우저와 공유기, DNS 서버, 사이트 운영자가 정한 TTL까지 영향을 줄 수 있어 어느 지점에서 오래된 주소가 반환되는지 나눠보는 편이 좋습니다.

## 1. 다른 기기로 비교

같은 와이파이에 연결된 스마트폰에서도 같은 사이트가 안 열리는지 먼저 확인합니다. PC 한 대만 문제라면 윈도우나 브라우저 캐시 가능성이 커지고 모든 기기가 같다면 공유기나 상위 DNS 쪽으로 범위가 넓어집니다.

휴대폰에서 와이파이를 끄고 모바일 데이터로 접속했을 때 정상인지 보는 것도 도움이 됩니다. 집 인터넷에서만 문제가 생기는지 빠르게 구분할 수 있습니다.

## 2. 윈도우 캐시 지우기

명령 프롬프트에서 ipconfig 명령의 DNS 캐시 초기화 기능을 사용하면 윈도우가 저장한 도메인 정보를 비울 수 있습니다. 작업 뒤 같은 도메인을 다시 조회해 새 주소를 받는지 확인합니다.

이 단계는 내 PC 캐시만 정리합니다. 공유기와 DNS 사업자가 여전히 이전 주소를 반환하고 있다면 같은 결과가 다시 들어오므로 한 번 지웠는데 안 됐다고 명령을 반복할 필요는 없습니다.

## 3. 브라우저가 다른 DNS를 쓸 수 있다

크롬과 파이어폭스 같은 브라우저는 자체 DNS 캐시와 보안 DNS 기능을 사용할 수 있습니다. 윈도우 DNS를 바꿨는데 브라우저만 결과가 다르다면 브라우저 설정과 재시작을 함께 확인합니다.

시크릿 창이 모든 DNS 캐시를 완전히 우회해주는 것은 아닙니다. 일반 창과 시크릿 창의 차이만으로 DNS 문제라고 단정하지 않는 편이 좋습니다.

## 4. TTL은 기다려야 할 때도 있다

도메인 소유자가 DNS 레코드를 변경하면 기존 정보가 TTL 시간 동안 여러 DNS 서버에 남아 있을 수 있습니다. 사이트를 방금 이전했다면 내 PC 캐시를 지워도 상위 서버가 이전 주소를 돌려주는 시간이 존재할 수 있습니다.

여러 지역의 DNS 조회 결과를 비교하거나 다른 공용 DNS에서 반환되는 주소를 확인하면 전파 상태를 판단하기 쉽습니다. 무조건 공유기를 초기화할 문제는 아닙니다.

## 5. 호스트 파일과 보안 프로그램

특정 PC에서만 계속 엉뚱한 주소로 연결된다면 윈도우 호스트 파일이나 보안 프로그램이 도메인을 직접 가로채고 있지 않은지도 확인합니다. 예전에 광고 차단이나 개발 테스트를 위해 수동 주소를 넣어둔 경우가 의외로 남아 있을 수 있습니다.

DNS 캐시 삭제는 좋은 첫 단계지만 만능 해결책은 아닙니다. 다른 기기와 다른 네트워크 비교를 먼저 하면 캐시를 볼지 DNS 서버를 볼지 훨씬 빨리 결정할 수 있습니다.

사이트 운영자가 DNS를 방금 바꾼 상황이라면 사용자마다 새 서버가 보이는 시점이 조금 다를 수 있습니다. 이런 전파 시간은 내 컴퓨터 고장이 아니므로 변경 시각과 TTL을 기준으로 기다려야 할 때도 있습니다.

캐시를 지웠다는 사실보다 새 주소가 어디에서 다시 들어오는지가 중요합니다. PC, 브라우저, 공유기, 상위 DNS를 나눠보면 같은 명령을 반복하는 시간을 줄일 수 있습니다.

특정 브라우저에서만 안 열리고 다른 브라우저에서는 정상이라면 운영체제 전체보다 브라우저 설정을 먼저 보는 것이 맞습니다. 반대로 모든 앱과 모든 기기에서 같은 도메인만 실패하면 상위 DNS나 사이트 자체 문제까지 범위를 넓혀야 합니다.

## 7. 캐시 삭제가 효과 있는 증상만 골라보기

문제가 있을 때 특정 사이트만 옛 주소로 가는지을 기록해 두면 정상 상태와 비교하기 좋습니다. 특히 다른 기기와 다른 브라우저에서 같은 도메인 비교하는 과정에서 차이가 분명하게 드러나는 경우가 많습니다. DNS 캐시는 저장된 주소 결과를 비우는 기능이라 전체 인터넷 끊김에는 우선순위가 낮음이라는 사실을 기억하시면 필요 없는 설정 변경을 줄일 수 있습니다.

처음부터 인터넷이 느릴 때마다 반복 실행하는 것보다는 확인 가능한 것부터 바꾸시는 게 안전합니다. 브라우저 재시작과 DNS 서버 설정도 함께 확인해 보시고 결과를 남겨 두십시오. 그래도 같은 현상이 이어진다면 hosts 파일이나 VPN 내부 DNS 문제는 별도로 봐야 함하면서 범위를 넓히는 순서가 효율적입니다.
