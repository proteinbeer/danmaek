온라인 게임이나 콘솔에서 NAT 타입이 ’엄격’으로 표시돼도 인터넷 속도가
느리다는 뜻은 아닙니다. 다운로드와 영상은 정상인데 파티 참가, 음성 채팅,
P2P 연결이나 호스트 기능만 실패한다면 공유기가 외부 연결을 처리하는
구조부터 확인하는 편이 빠릅니다.

## 1. 표시보다 실제로 실패하는 기능을 봅니다

게임과 플랫폼마다 NAT 상태의 명칭과 판정 기준이 다릅니다. 매칭, 파티,
음성 채팅, 친구 참가가 모두 정상이라면 NAT 표시만 바꾸기 위해 DMZ 같은
큰 설정을 적용할 이유는 적습니다. 반대로 특정 친구의 방 참가나 P2P
기능이 반복해서 실패한다면 다음 단계로 넘어갑니다.

## 2. 공유기의 WAN IP와 공인 IP를 비교합니다

공유기 관리자 화면에서 WAN IP 또는 Internet IP를 확인합니다. PC의
ipconfig에 나오는 내부 IP가 아니라 공유기가 인터넷 쪽에서 받은
주소입니다. 이를 웹에서 확인되는 공인 IPv4와 비교합니다.

두 값이 같다면 공유기가 공인 IPv4를 직접 받고 있을 가능성이 높습니다.
다르면 공유기 앞에 다른 라우터가 있거나 통신사 CGNAT 환경일 수 있습니다.

## 3. 공유기가 두 대라면 이중 NAT를 확인합니다

인터넷 → 통신사 공유기 → 개인 공유기 → PC/콘솔 구조에서 두 공유기가 모두
라우터 모드라면 NAT가 두 번 일어날 수 있습니다. 두 번째 공유기를
와이파이 확장용으로만 쓴다면 AP 모드로 바꿔 NAT 단계를 하나로 줄일 수
있습니다. IPTV나 인터넷 전화가 연결된 통신사 장비는 설정 변경 전에
서비스 구성을 확인합니다.

## 4. 공유기가 한 대인데 주소가 다르면 CGNAT를 봅니다

집에 라우터가 한 대뿐인데 WAN IPv4와 외부 공인 IPv4가 다르면 통신사
구간의 NAT 가능성이 있습니다. 특히 WAN 주소가
100.64.0.0~100.127.255.255라면 CGNAT 여부를 확인할 이유가 큽니다. 이
경우 집 공유기의 포트포워딩만으로는 통신사 NAT를 제어할 수 없습니다.

## 5. 구조가 정상이라면 UPnP를 확인합니다

공유기가 공인 IPv4를 직접 받고 이중 NAT도 아니라면 UPnP 상태를 봅니다.
지원하는 게임이나 콘솔은 필요한 포트 매핑을 자동으로 요청할 수 있습니다.
설정을 변경했다면 게임을 완전히 종료하거나 콘솔을 재시작한 뒤 같은
기능으로 다시 확인합니다.

## 6. 수동 포트포워딩은 필요한 경우에만 사용합니다

UPnP로도 필요한 연결이 만들어지지 않을 때 게임이나 플랫폼의 공식 지원
문서에서 요구하는 포트를 확인합니다. 대상 PC나 콘솔의 내부 IP가 바뀌지
않도록 DHCP 예약을 함께 사용할 수도 있습니다.

NAT 문제의 확인 순서는
실제 실패 기능 → WAN IP 비교 → 이중 NAT → CGNAT → UPnP → 필요한 포트포워딩으로
잡으면 됩니다. 기가인터넷 여부와 NAT 상태는 별개의 문제이므로 속도
설정부터 건드릴 필요는 없습니다.
