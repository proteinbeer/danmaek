온라인 게임이나 콘솔에서 NAT 타입이 ‘엄격’으로 표시되면 포트포워딩부터 검색하기 쉽습니다. 하지만 먼저 확인할 것은 포트 번호가 아니라 인터넷이 집 안까지 들어오는 구조입니다. 공유기가 두 번 주소를 변환하는 이중 NAT나 통신사의 CGNAT 환경이라면, 내 공유기에서 포트를 열어도 문제가 그대로 남을 수 있습니다.

게임 다운로드와 유튜브는 멀쩡한데 파티 참가, 음성 채팅, 친구와의 직접 연결, 호스트 기능만 실패한다면 아래 순서대로 확인해보시면 됩니다.

## 1. NAT 표시보다 실제로 안 되는 기능부터 확인

NAT 타입은 게임과 플랫폼마다 표시 기준이 다릅니다. 따라서 ‘엄격’이라는 글자만 보고 설정을 크게 바꾸기보다는 실제로 어떤 기능이 실패하는지 먼저 확인하는 편이 좋습니다.

게임 매칭은 정상인데 음성 채팅만 안 된다면 NAT 외에 게임 설정이나 음성 서비스 문제일 수도 있습니다. 반대로 파티 참가와 호스트 연결이 반복해서 실패하고 다른 인터넷 기능은 정상이라면 NAT 구조를 확인할 이유가 충분합니다.

설정을 바꿀 때는 한 번에 하나씩 변경하고 게임이나 콘솔을 다시 실행한 뒤 같은 기능으로 결과를 비교합니다. 여러 설정을 동시에 바꾸면 무엇이 원인이었는지 알기 어려워집니다.

## 2. 공유기 WAN 주소부터 확인

집에서 사용하는 공유기 관리 화면에 들어가 WAN 또는 인터넷 IP 주소를 확인합니다. 그다음 인터넷에서 확인되는 자신의 공인 IP와 비교합니다.

두 주소가 같다면 현재 공유기가 공인 IP를 직접 받고 있을 가능성이 높습니다. 서로 다르다면 공유기 앞에 다른 라우터가 있거나 통신사에서 CGNAT를 사용하는 환경일 수 있습니다.

특히 통신사에서 설치한 장비에 개인 공유기를 추가로 연결했다면 장비 두 대가 모두 라우터 역할을 하고 있는지 확인해보는 것이 좋습니다.

## 3. 공유기가 두 대라면 이중 NAT부터 해결

예를 들어 연결 구조가 아래와 같다면 이중 NAT가 발생할 수 있습니다.

```
인터넷 → 통신사 공유기 → 개인 공유기 → PC 또는 콘솔
```

두 공유기가 모두 NAT를 수행하면 게임이 외부 연결을 만들 때 주소 변환 단계를 두 번 통과해야 합니다. 웹사이트나 영상 스트리밍에는 문제가 없으면서 게임의 NAT 상태만 엄격하게 표시될 수 있는 이유입니다.

개인 공유기를 단순히 와이파이 확장이나 유선 연결용으로 사용하고 있다면 AP 모드로 변경해 NAT 단계를 하나로 줄일 수 있습니다. 반대로 통신사 장비를 브리지 모드로 바꾸는 방법도 있지만 IPTV나 전화 같은 부가 서비스가 연결돼 있다면 설정을 바꾸기 전에 통신사 구성을 확인하는 편이 안전합니다.

## 4. 공유기가 한 대인데 WAN IP가 다르다면 CGNAT 확인

집에 라우터가 한 대뿐인데 공유기의 WAN 주소와 인터넷에서 확인한 공인 IP가 다르다면 CGNAT 가능성을 확인합니다.

CGNAT에서는 여러 가입자가 통신사의 공인 IPv4 주소를 공유합니다. 이 경우 사용자가 제어하는 공유기보다 바깥쪽에서 한 번 더 NAT가 이루어지기 때문에 공유기에서 포트포워딩을 설정해도 외부 연결이 그대로 막힐 수 있습니다.

이 상황에서는 공유기 설정을 계속 바꾸기보다 인터넷 제공업체에 공인 IPv4를 받을 수 있는지 문의하는 것이 빠릅니다. 사용하는 게임과 회선이 IPv6 연결을 지원한다면 IPv6가 대안이 되는 경우도 있습니다.

## 5. 구조에 문제가 없다면 UPnP 확인

공유기가 공인 IP를 직접 받고 있고 이중 NAT도 아니라면 UPnP 상태를 확인합니다.

UPnP가 활성화되어 있으면 게임이나 콘솔이 필요한 포트를 공유기에 자동으로 요청할 수 있습니다. 가정에서 콘솔이나 게임용 PC를 사용하는 경우 수동으로 여러 포트를 지정하는 것보다 관리하기 편합니다.

UPnP를 켠 뒤에는 실행 중이던 게임을 완전히 종료하거나 콘솔을 재부팅한 다음 NAT 상태를 다시 확인합니다. 기존 연결 정보가 남아 있으면 설정 변경이 바로 반영되지 않는 것처럼 보일 수 있습니다.

다만 UPnP는 내부 네트워크의 기기를 신뢰한다는 전제가 있으므로 출처를 알 수 없는 기기가 많이 연결되는 환경이라면 사용 여부를 따로 판단하는 것이 좋습니다.

## 6. 포트포워딩은 마지막에 필요한 만큼만

이중 NAT와 CGNAT가 아니고 UPnP로도 해결되지 않을 때 수동 포트포워딩을 검토합니다.

이때는 게임이나 플랫폼의 공식 지원 문서에서 요구하는 포트를 확인하고 필요한 범위만 설정합니다. 대상 PC나 콘솔의 내부 IP가 바뀌면 포트포워딩 규칙이 다른 기기를 가리킬 수 있으므로 DHCP 예약을 함께 사용하는 것이 편합니다.

인터넷에서 찾은 긴 포트 목록을 이유 없이 전부 열거나 NAT 문제를 해결하기 위해 PC나 콘솔을 장기간 DMZ에 두는 방식은 권장하지 않습니다.

## 어디에서 막혔는지 빠르게 구분하는 법

공유기 WAN IP와 공인 IP가 같고 공유기도 한 대라면 UPnP와 게임별 설정을 먼저 확인합니다.

WAN IP와 공인 IP가 다르고 집에 공유기가 두 대라면 이중 NAT를 의심할 수 있습니다.

WAN IP와 공인 IP가 다른데 집에 라우터가 한 대뿐이라면 CGNAT 여부를 인터넷 제공업체에 확인해보는 것이 좋습니다.

그리고 NAT가 엄격하다는 이유만으로 인터넷 요금제를 올릴 필요는 없습니다. NAT 타입은 회선의 다운로드 속도와 별개의 문제입니다. 기가인터넷에서도 NAT가 엄격할 수 있고, 더 느린 회선에서도 연결 구조가 단순하면 NAT 상태에는 문제가 없을 수 있습니다.

결국 확인 순서는 복잡하지 않습니다. 실제로 실패하는 기능을 확인하고, 공유기의 WAN 주소를 비교한 뒤, 이중 NAT와 CGNAT를 먼저 제외합니다. 그다음 UPnP를 확인하고 필요한 경우에만 포트포워딩으로 넘어가면 됩니다.
