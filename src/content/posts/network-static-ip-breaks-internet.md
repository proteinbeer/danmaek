NAS나 게임 서버 때문에 Windows에 고정 IP를 넣었다가 인터넷이 끊기는
경우가 있습니다. IP 주소 하나만 원하는 숫자로 바꾸는 것이 아니라 IP,
서브넷, 기본 게이트웨이, DNS가 현재 네트워크와 맞아야 합니다.

## 자동 DHCP로 복구해 정상값을 기록합니다

IPv4 설정을 ’자동으로 IP 주소 받기’와 ’DNS 서버 주소 자동으로 받기’로
되돌립니다. 인터넷이 다시 된다면 ipconfig /all로 정상 상태의 IPv4,
서브넷, 기본 게이트웨이, DNS를 기록합니다.

예를 들어 정상 상태가
192.168.0.73 / 255.255.255.0 / 게이트웨이 192.168.0.1이라면 일반적인 /24
구성에서 192.168.1.50을 임의로 넣으면 공유기와 다른 네트워크가 됩니다.

## 게이트웨이를 빼먹지 않았는지 봅니다

같은 LAN의 장비는 보이는데 인터넷만 안 된다면 기본 게이트웨이를
확인합니다. 가정에서는 보통 공유기 주소가 들어갑니다.

## DNS 문제는 따로 구분합니다

IP와 게이트웨이는 정상인데 DNS만 잘못됐다면 숫자 IP 통신은 되면서 도메인
이름 접속이 실패할 수 있습니다. 게이트웨이 연결과 DNS 조회를 나눠
확인하면 원인을 찾기 쉽습니다.

## 주소 충돌 가능성도 확인합니다

수동으로 지정한 주소가 DHCP 자동 배정 범위 안에 있으면 다른 기기와
충돌할 수 있습니다. 단순히 포트포워딩 대상 PC의 주소를 유지하려는
목적이라면 Windows에 직접 고정 IP를 넣는 대신 공유기의 DHCP 예약을 쓰는
방법도 있습니다.

고정 IP 설정 직후 문제가 생겼다면 네트워크 초기화보다 자동 DHCP로
정상값을 확보하는 것이 먼저입니다. 그 값과 수동 설정을 비교하면 틀린
항목을 훨씬 빨리 찾을 수 있습니다.
