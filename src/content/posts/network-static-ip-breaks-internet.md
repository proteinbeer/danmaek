NAS나 프린터, 게임 서버 때문에 PC에 고정 IP를 넣었다가 인터넷이 끊기는 경우가 있습니다. IP 주소 한 칸만 맞으면 된다고 생각하기 쉽지만 같은 네트워크에서 통신하려면 서브넷과 기본 게이트웨이, DNS까지 현재 공유기 구조와 맞아야 합니다.

가장 안전한 방법은 고정 설정 전에 자동으로 받던 정상 값을 기록하는 것입니다. 정상 상태의 IP와 게이트웨이, DNS를 기준으로 무엇이 달라졌는지 비교하면 무작정 숫자를 바꾸는 일을 줄일 수 있습니다.

1. 게이트웨이가 가장 중요

PC의 IP를 현재 공유기 대역에 맞게 넣었더라도 기본 게이트웨이를 다른 대역의 주소로 적으면 집 안 장치와 일부 통신은 돼도 인터넷으로 나가지 못할 수 있습니다. 게이트웨이는 보통 현재 공유기의 내부 주소를 사용합니다.

공유기를 바꾼 뒤 예전 게이트웨이 주소를 그대로 사용하고 있지 않은지 확인합니다. 공유기마다 기본 주소가 다를 수 있어 이전 설정 복사가 항상 정답은 아닙니다.

2. 서브넷이 맞지 않는 경우

서브넷 마스크가 현재 네트워크와 맞지 않으면 어떤 주소를 같은 내부망으로 볼지 판단이 달라집니다. 일반 가정에서는 자동 설정에서 받은 값을 그대로 참고하는 편이 안전합니다.

인터넷에서 본 예시 값을 그대로 입력하기보다 내 PC가 정상 상태에서 어떤 값을 받았는지 기록하는 것이 중요합니다. 네트워크 구조는 집마다 다를 수 있습니다.

3. DNS만 잘못된 상황

공유기 주소에는 접속되고 외부 IP에는 통신되는데 사이트 이름만 열리지 않는다면 DNS 설정을 확인합니다. 고정 IP를 넣으면서 DNS 칸을 비우거나 잘못된 서버를 입력하면 인터넷이 끊긴 것처럼 느낄 수 있습니다.

이 경우 회선과 게이트웨이는 정상입니다. IP 주소 접속과 도메인 접속을 나눠보면 DNS 문제인지 빠르게 구분할 수 있습니다.

4. 주소 충돌

직접 고정한 IP가 공유기의 DHCP 자동 배분 범위 안에 있으면 다른 기기가 같은 주소를 받을 수 있습니다. 처음에는 잘 되다가 며칠 뒤 갑자기 충돌하는 이유가 될 수 있습니다.

공유기에서 주소 예약을 사용하거나 수동 주소를 쓸 때는 DHCP 범위와 겹치지 않도록 관리해야 합니다. 같은 IP를 두 장비가 쓰면 둘 다 간헐적으로 끊길 수 있습니다.

5. DHCP 예약이 더 간단

항상 같은 주소가 필요한 이유가 포트포워딩이나 NAS 접근이라면 PC에 직접 고정 IP를 넣는 대신 DHCP 예약을 고려할 수 있습니다. 장비는 자동 설정을 유지하고 공유기가 같은 주소를 계속 배정합니다.

이 방식은 공유기의 DNS와 게이트웨이가 바뀌었을 때 장비 설정을 일일이 수정할 필요가 적습니다. 가정에서는 직접 고정값을 여러 기기에 흩어놓는 것보다 예약 기능이 관리하기 쉬운 경우가 많습니다.

설정이 정상으로 돌아오면 현재 공유기의 주소 대역과 DHCP 범위를 메모해두면 다음 장비를 추가할 때 편합니다. 숫자를 외우는 것보다 공유기 한 곳에서 예약과 연결 장치를 관리하는 방식이 실수를 줄여줍니다.

고정 IP 자체가 나쁜 설정은 아닙니다. 다만 목적이 주소 유지뿐이라면 DHCP 예약이 더 단순하고, 직접 고정해야 한다면 정상 자동값을 기준으로 게이트웨이와 DNS까지 함께 맞추셔야 합니다.

고정 설정을 지우고 자동으로 되돌렸는데도 인터넷이 안 되면 어댑터를 한 번 다시 연결해 새 DHCP 정보를 받게 하시면 됩니다. 이전 수동 값이 화면에서 바뀌었더라도 연결이 갱신되기 전까지 기존 상태가 남아 보일 수 있습니다.
