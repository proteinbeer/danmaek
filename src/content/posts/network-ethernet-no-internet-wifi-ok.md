같은 PC에서 와이파이는 정상인데 랜선을 연결하면 인터넷 없음이 뜬다면 통신사 회선 전체가 죽은 상황은 아닐 가능성이 큽니다. 무선은 이미 인터넷에 나가고 있으므로 유선 랜카드에서 공유기 포트까지의 경로를 따로 확인하는 것이 빠릅니다.

이때 공유기 전체를 초기화하면 정상인 와이파이 설정까지 건드리게 됩니다. 링크 속도, IP 주소, 랜선과 포트 순서로 유선만 좁혀보시면 원인을 훨씬 적게 건드리고 찾을 수 있습니다.

1. 링크 연결부터 확인

윈도우의 이더넷 상태가 연결됨으로 표시되는지 확인합니다. 연결 자체가 잡히지 않는다면 DNS나 IP보다 랜선과 공유기 포트, 랜카드의 물리 링크를 먼저 봐야 합니다.

랜포트의 표시등이 있다면 불이 들어오는지도 확인합니다. 다른 정상 랜선을 꽂았을 때 바로 연결되면 기존 케이블이나 벽면 배선이 원인이었을 가능성이 높습니다.

2. 169.254 주소 확인

이더넷은 연결됐다고 나오지만 IPv4 주소가 169.254로 시작하면 공유기에서 주소를 받지 못한 상태입니다. 와이파이는 정상이라도 유선 랜카드만 DHCP 통신에 실패할 수 있습니다.

같은 공유기 포트와 랜선을 다른 기기에 연결해 주소를 정상적으로 받는지 비교합니다. 다른 기기도 실패하면 PC 설정보다 포트나 케이블 쪽을 먼저 바꾸는 것이 합리적입니다.

3. 수동 IP 흔적

예전에 사무실이나 NAS 테스트 때문에 유선 어댑터에 고정 IP를 넣었다면 집 네트워크와 맞지 않는 값이 남아 있을 수 있습니다. IPv4 설정에서 IP와 DNS를 자동으로 받도록 돌린 뒤 다시 연결해봅니다.

와이파이 어댑터와 이더넷 어댑터는 설정이 따로입니다. 와이파이가 정상이라는 사실이 유선 IP 설정까지 정상이라는 뜻은 아닙니다.

4. 랜카드 드라이버

윈도우 업데이트나 드라이버 변경 뒤부터 증상이 시작됐다면 장치 관리자에서 랜카드 상태를 확인합니다. 장치를 제거해 무조건 새로 잡기 전에 제조사 드라이버가 있는지 확인하고 현재 버전과 비교하는 편이 좋습니다.

USB 랜카드를 사용 중이라면 다른 USB 포트에서도 확인합니다. 허브를 거치던 환경이라면 PC 본체에 직접 연결해 전원과 연결 문제를 함께 배제할 수 있습니다.

진단할 때는 와이파이를 잠시 끄고 이더넷만 남겨보는 것이 좋습니다. 두 연결이 동시에 켜져 있으면 실제 인터넷 트래픽이 어느 어댑터로 나가는지 헷갈릴 수 있습니다.

유선만 켠 상태에서 공유기 주소와 외부 IP, 도메인 주소 순으로 확인하면 링크, 인터넷, DNS 문제를 각각 나눌 수 있습니다. 회선 전체 초기화보다 이렇게 유선 경로를 분리하는 편이 훨씬 빠릅니다.

이더넷 문제가 해결되면 다시 와이파이를 켜고 두 연결의 우선순위가 의도대로 동작하는지 확인하시면 됩니다. 데스크톱에서는 안정성과 지연 때문에 유선을 주 연결로 두는 편이 게임에도 유리합니다.

와이파이가 정상인 상황은 오히려 좋은 단서입니다. 인터넷 전체가 아니라 유선 경로만 보면 되므로 문제 범위를 절반 이하로 줄인 상태에서 시작할 수 있습니다.

랜선 연결 직후 몇 초 동안 주소를 받는 시간이 필요한 경우도 있습니다. 연결하자마자 인터넷 없음이 보인다고 바로 설정을 바꾸기보다 잠시 기다린 뒤 IP 주소와 게이트웨이가 정상적으로 생겼는지 확인하는 편이 좋습니다.
