마이크로소프트가 패스키와 다중 인증, 통합 로그인을 업데이트해야 한다는 안내로 위장한 피싱 공격을 경고했습니다. 공격자는 회사 IT 지원팀인 것처럼 전화나 문자를 보내 마이크로소프트 365 계정을 탈취하고 데이터를 빼내고 있습니다.

중요한 점은 패스키 기술 자체가 뚫린 사건이 아니라는 것입니다. 공격자는 패스키가 안전하다는 이미지를 이용해 이용자가 가짜 로그인 페이지에서 다른 인증 정보를 넘기도록 속이죠.

## 1. IT 지원팀을 사칭해 먼저 연락

공격자는 표적 회사와 직원 정보를 미리 조사한 뒤 IT 헬프데스크 직원인 것처럼 전화하거나 메시지를 보냅니다. 패스키나 다중 인증 설정을 즉시 갱신하지 않으면 회사 시스템 접근이 차단된다는 식으로 긴급함을 만듭니다.

평소 회사에서 실제로 보안 설정 변경 공지가 자주 온다면 피해자는 의심하기 어렵습니다. 기술보다 조직 내부 절차와 말투를 흉내 내는 사회공학 공격입니다.

## 2. 문자로 가짜 마이크로소프트 페이지 전송

피해자는 개인 휴대전화 문자로 받은 링크를 열고 마이크로소프트 로그인 화면과 비슷하게 만든 사이트로 이동하죠. 여기서 계정 정보와 인증 과정을 입력하도록 유도합니다.

주소창을 자세히 보지 않으면 실제 로그인 페이지처럼 느껴질 수 있습니다. 회사 로고와 익숙한 색상, 안내 문구를 복제하는 것은 어렵지 않습니다.

## 3. 패스키 자체를 등록하는 공격은 아니다

마이크로소프트는 공격자가 실제로 피해자 계정에 패스키를 등록하려는 것이 아니라고 설명했죠. 패스키라는 단어를 보안 공지의 명분으로 사용해 다른 로그인 정보와 세션을 훔치는 것이 목적입니다.

그래서 이번 사건을 패스키가 안전하지 않다는 증거로 볼 필요는 없습니다. 오히려 강한 보안 기능도 사용자가 가짜 지원 요청을 믿으면 우회될 수 있다는 사례이죠.

## 4. 샤이니헌터스와 다른 협박 조직 연계

마이크로소프트는 샤이니헌터스와 헬릭스 등 데이터 절취와 협박에 연계된 위협 행위자들이 이런 공격을 사용한다고 밝혔습니다. 2026년 5월부터 여러 조직에서 활동이 관찰됐습니다.

목적은 계정 하나를 훔치는 데서 끝나지 않습니다. 마이크로소프트 365 안의 메일과 파일을 가져가 회사에 돈을 요구하는 단계까지 이어질 수 있습니다.

## 5. 보안 설정은 메시지 링크로 들어가지 않는다

가장 간단한 대응은 전화나 문자로 받은 링크에서 보안 설정을 바꾸지 않는 것입니다. 회사 포털과 마이크로소프트 공식 주소를 직접 열고 동일한 공지가 있는지 확인하시면 되죠.

IT 부서도 직원에게 비밀번호와 인증 코드를 직접 요구하지 않는다는 원칙을 반복해서 교육할 필요가 있습니다. 강한 인증 기술보다 사용자가 정상 절차를 아는 것이 마지막 방어선이 되는 경우가 많습니다.

지금 단계에서는 한 번의 발표나 사례만으로 전체 흐름을 단정하기는 어렵죠. 후속 업데이트와 공식 설명, 실제 이용자 반응이 같은 방향으로 이어지는지 확인하시면 처음 뉴스에서 보이지 않던 의미까지 더 정확하게 판단할 수 있습니다.

## 6. 회사에서 정해둘 한 가지 규칙

직원이 기억하기 쉬운 규칙은 IT 지원팀이 먼저 연락해도 문자 링크에서 로그인하지 않는 것입니다. 보안 설정 변경이 필요하면 회사 포털을 직접 열거나 사내에 등록된 번호로 IT 부서에 다시 연락하도록 절차를 고정하면 공격자가 만드는 긴급함을 끊을 수 있죠.

패스키와 다중 인증이 보급될수록 공격자는 기술을 깨기보다 설정을 바꿔야 한다는 거짓말로 사용자를 움직이려 할 가능성이 큽니다. 보안 교육도 비밀번호를 복잡하게 만드는 법에서 정상적인 지원 절차를 구분하는 법으로 바뀌어야 합니다.

## 7. 패스키가 강해질수록 사람을 노린다

패스키는 비밀번호를 직접 입력하지 않아도 되고 피싱 사이트에서 인증하기 어렵게 설계된 방식이죠. 그래서 공격자도 기술 자체를 깨기보다 이용자를 속여 계정 복구나 보안 설정 변경 같은 다른 경로로 끌고 갑니다. 인증 기술이 좋아질수록 전화와 문자, 가짜 지원센터 같은 사회공학이 더 중요해질 수 있다는 점을 기억할 필요가 있습니다.
